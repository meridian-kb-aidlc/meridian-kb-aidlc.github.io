01 / THE PROBLEM

Faster code is not
the same as safer change.

Coding agents accelerate implementation. The hard part is knowing what a change means for the rest of the system.

01

No shared system map

Repositories are connected in production, but agents and developers often explore them in isolation.

02

Invisible blast radius

A local change can affect downstream consumers, API contracts, and services owned by another team.

03

Knowledge drift

Architecture diagrams, ownership records, and wiki pages can fall behind the code they describe.

04

Governance gaps

People and agents need context scoped to the right organization, portfolio, and application.

02 / THE SOLUTION

A living, governed
knowledge graph.

Declare architecture as structured facts. Compile a versioned system map. Deliver relevant context through the tools people and agents already use.

  1. 1

    Declare

    OKF YAML describes services, modules, contracts, datastores, teams, and conventions.

    Git + Open Knowledge Format
  2. 2

    Compile

    Validate facts and build relationships, impact sets, graph snapshots, and repository instructions.

    Versioned knowledge builds
  3. 3

    Connect

    Combine application knowledge at portfolio and organization scope to reveal cross-repo relationships.

    Organization / Portfolio / Application
  4. 4

    Use

    Agents query MCP tools; people explore the same knowledge through GraphQL and the web interface.

    MCP + GraphQL + AGENTS.md

CONTEXT AT THE POINT OF CHANGE

Ask better questions.
Start in the right place.

Use module context to locate relevant ownership and conventions. Use impact queries to identify affected consumers. Read the implementation and verify the change.

→ What module owns this file?

→ What depends on this contract?

→ Which conventions apply here?

→ What context was this agent given?

03 / THE VALUE

Less rediscovery.
More informed development.

DEVELOPMENT

Make change impact visible

Give reviewers and agents a shared view of touched modules, dependent services, contracts, and owners. PR advice informs review; it is not a blocking safety gate.

ONBOARDING & AUDIT

Make context traceable

Explore structured architecture instead of piecing together disconnected documents. Versioned builds and audit records show the source of served context.

AI-DRIVEN DEVELOPMENT

Measure the benefit

The evaluation harness compares tasks with and without Meridian context, tracking correctness, time, token usage when reported, and change scope.

Evidence over promises. Focused context may reduce unnecessary exploration, but token-cost savings and quality improvements need real A/B measurements. OKF must stay accurate; agents still need to inspect code and run checks.

OPEN AGENT ECOSYSTEM

One context plane.
Different agents.

Meridian uses MCP for live context, AGENTS.md for repository instructions, and a Goose adapter for evaluation. OKF is Meridian's own knowledge format.
